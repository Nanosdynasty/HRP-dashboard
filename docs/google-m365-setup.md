This change is prepared in code. It becomes live only after the providers are configured and tested. Google verifies a requester; it does not read the requester's Gmail messages. The initial reset sender is the owner's personal `dynasty9939@outlook.com` mailbox, which needs delegated Microsoft consent. It does not grant sign-in or dashboard permissions.

Both redirect URIs below are saved and were verified after reopening the client. The client ID is in the ignored local `.env`; the server has no usable client secret yet. 1. In [Google Cloud Console](https://console.cloud.google.com/apis/credentials), create a project for the dashboard. Configure **Google Auth Platform** branding and select an **External** audience. Request only `openid`, `profile`, and `email`.
2. Create an OAuth client of type **Web application**. Add these exact redirect URIs for the origins you actually use:
   - `http://localhost:8000/auth/google/callback`
   - `https://howe-robinson-dashboard.centralindia.cloudapp.azure.com/auth/google/callback`
   If local access uses `127.0.0.1`, register that callback separately; it is not interchangeable with `localhost`.
3. Keep the Google client secret in the private server environment. Set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`; do not put either value in browser JavaScript or source control. Restart the app.
4. Test one Gmail account through **Request access with Google / Gmail**. Its request should appear in the owner's Access requests area with Google issuer and subject. Before approval, the requester must receive no dashboard data. After approval, test section grants, password setup, authenticator setup and login.
5. Review the Google console's audience/publishing state before inviting other users. Google may require additional branding or testing setup. The app requests no Gmail mail scopes. See [Google's server OAuth flow](https://developers.google.com/identity/protocols/oauth2/web-server) and [ID-token validation](https://developers.google.com/identity/openid-connect/openid-connect).

## 3. Later alternative: a Microsoft 365 work mailbox

1. Choose an existing Exchange Online mailbox dedicated to dashboard security mail. Record only its address in `MS365_MAIL_SENDER`, and remove `MAIL_PERSONAL_SENDER` so the application uses the work-mail mode.
2. In the **mailbox's Microsoft 365 tenant**, create a separate Entra app registration for mail delivery. Record its tenant ID and client ID as `MS365_MAIL_TENANT_ID` and `MS365_MAIL_CLIENT_ID`. Create its credential privately as `MS365_MAIL_CLIENT_SECRET`. Do not reuse the dashboard sign-in app's credential.
3. Have an Exchange Online administrator grant **Application Mail.Send** through [Exchange application RBAC](https://learn.microsoft.com/en-us/exchange/permissions-exo/application-rbac), scoped to the chosen sender mailbox. Do not add an unscoped Entra `Mail.Send` grant: Microsoft documents that Entra and Exchange grants are additive. Use `Test-ServicePrincipalAuthorization` for the sender and an unrelated mailbox, then test actual Graph delivery. Permission propagation may take time.
4. Store the four `MS365_MAIL_*` values in the VM's private environment file and restart the app. The reset page uses [Graph `sendMail`](https://learn.microsoft.com/en-us/graph/api/user-sendmail?view=graph-rest-1.0) with app-only credentials. No SMTP password or mailbox-read permission is needed.
5. Test reset to an **approved** account: request a link, receive it, enter the enrolled authenticator code and a new password, and confirm the old password and old sessions no longer work. Verify unknown/unapproved addresses receive the same public acknowledgment and no email. Do not publish the sender configuration until these checks pass.

The app does not print secrets or reset tokens to logs. A reset link lasts 15 minutes and is single-use; its token is in the URL fragment, then submitted in the form body with a CSRF token. Existing owner-assisted lost-factor recovery remains separate. Existing recovery codes in already-enrolled accounts remain valid until a deliberate migration; the code-free enrolment described in the compact guide has **not** been activated yet.
